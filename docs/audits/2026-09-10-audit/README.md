## app-ux

The logged-in product is structurally sound (URL-per-screen with working browser back, focus-trapped modals, undo on task/archive actions, good offline and failed-save handling, working CSV/ICS/packet exports, a complete submit → accept → next-cycle lifecycle) but it is not launchable as-is: any second keystroke in the log-activity sheet unmounts the whole app (all five controlled fields read event.currentTarget inside a state updater), Sign out for real accounts points at a dead /signout-with-chatgpt URL, credentials can never be edited or deleted, and after a renewal is accepted Home's hero shows the closed cycle with a live countdown. Beyond those P1s, the experience reads as an iPhone app: one-credential hero with no multi-credential overview, 19–25-control "Quick add" sheet whose Save button sits below the fold on a 900px desktop, jargon-heavy regulatory copy (20-word check-in titles, "classification gaps", "countable units"), seven different labels for the same log action, stale "Today" tab references, and gamification (Levels/XP/weekly quests) occupying prime dashboard space for a compliance audience. First-credential setup is the biggest conversion wall: a 170-option native select, empty dates with server-only rules ("expiration must be March 31"), and a jargon attestation checkbox with no inline validation feedback. All exploration was done against the local dev app; the demo user's data is unchanged (one checklist toggle was undone), while a throwaway identity app-ux-new@example.test now holds four test credentials that cannot be removed from the UI (see app-ux-03). Screenshots and scripts are under the scratchpad app-ux/ and pw/ directories.

## landing-auth

The public funnel is fast and self-contained (7.7 KB landing, zero external requests, 138 ms TTFB, prod byte-identical to the repo files) and the auth backend is soundly engineered (scrypt, hashed single-use tokens, HMAC-signed HttpOnly/Secure/Lax cookie, Origin-based CSRF check, per-IP rate limits). But in production the funnel is non-functional end to end: verification email is unconfigured, the only contact address (support@itrackceu.com) has no MX and bounces, the "contact us" dead-end has no link, unverified accounts are purged after 7 days, and the web app's only Sign out control points at a 404 route from the old hosting platform. The iOS-shell compromises now actively damage the web product: the Safari/Firefox UA gate and the 401 Basic challenge deny the landing page to Google's inspection/verification tools, every social/link-preview bot, AI crawlers, SEO tools and uptime monitors, and hand browser fetches a native Basic-auth popup; robots.txt, sitemap, favicon, OG image and manifest all 303 to /login. Landing copy still sells beta, ads and a $9.99 Pro tier, says nothing about who the product is for (53 professions, 170 source-linked templates, 98 issuing bodies), offers no trust signals, privacy policy or terms, and every CTA fails WCAG AA contrast. Gateway-level fixes (drop UA/Basic gating, public static allowlist, real logout, email + DNS, privacy/terms pages) must ship regardless of and before the redesign; the visual, copy and a11y items are the redesign's acceptance criteria.

## a11y

The logged-in app is in unusually good accessibility shape for an 11k-line single-file client: axe (wcag2a/aa, 2.1, 2.2, best-practice) reports 0 violations across all 32 app runs (Home, Credentials, Credential detail, History, Profile, plus the Log activity sheet, the Set up a credential sheet and the Due-date check-ins sheet, at 1440x900 and 390x844, light and dark); the shared Modal has a real focus trap with inert siblings, Escape and focus restore; every pointer target is ≥44px except native checkboxes/radios that sit inside ≥44px labels; reduced-motion collapses every transition/animation to 0.01ms; text-spacing and 200%-zoom (720px) reflow are clean; and my own rendered-background contrast sampling of the 248 nodes axe left "incomplete" (gradient hero, translucent pills, dark scheme) found every one passing except text on the dimmed under-screen. The real defects are concentrated in shell logic rather than styling: the pushed credential-detail screen leaves the list screen underneath focusable and readable (three hidden tab stops and a second H1 before the back button), the Modal drops focus to body on close for every sheet that contains a React autoFocus field (18/18 cases: Set up a credential, Add task, Log submission), and the SPA never changes document.title or announces route changes. The public pages are the launch risk: every primary CTA and text link on landing/login/signup/reset/verify fails AA contrast (white on #007aff 4.02:1, #007aff on the grey page 3.60:1 — the app already fixed this with --accent-control, the pages did not), inputs have a 1.28:1 boundary, and the landing has no main landmark, a heading jump and colour-only links; prod serves byte-identical files so these apply to itrackceu.com today. Cross-cutting items to carry into the redesign: a ≥3:1 input boundary and a real 3px focus ring on fields, a consistent inline error pattern (today validation is native bubbles only), rem-based type, and urgency expressed in words rather than dot colour. Side effect: my toast probe snoozed one demo reminder (no UI or API exists to un-snooze); I deleted only that row (id e6c1557a…) from the Miniflare D1 SQLite state and verified the inbox is back to 2 check-ins; two other reminder_states rows written at 13:23 UTC predate any mutating step of mine and were left untouched.

## perf

Load performance of the production build is good and the bottleneck is bytes on slow networks, not CPU: the shell is 13.4 KB HTML (2.8 KB gz) + 97 KB CSS (19 KB gz) + 496 KB JS in 5 chunks (142 KB gz), 9 requests / 224 KB wire on a cold load; on an unthrottled desktop the trace shows FCP 46 ms, hydrated 47 ms, workspace data painted 65 ms, LCP 97 ms with zero long tasks, and on a 4x-throttled CPU + Fast-3G profile FCP 780 ms (skeleton), hydrated 1,291 ms, data painted 1,512 ms, LCP 1,565 ms, main thread busy only ~600 ms. Assets are immutable+gzip+ETag (verified on the identical build under workerd, and gzip pass-through verified on prod via /api/widget-summary), tesseract.js is lazy (7 KB gz chunk; 4.45 MB of core+language only on first scan, then SW-cached), no webfonts load, and the Railway proxy adds negligible overhead (healthz TTFB 175-257 ms ≈ landing TTFB 157-255 ms from NYC; per-request session SQLite cost measured 0.02 ms). The dist/ I inspected is from Aug 12 08:22:24 2026, i.e. HEAD 3f477e6 (app source last changed 2026-08-11), so it is current. The material problems are elsewhere: typing normally into the Log-activity title field crashes the whole app to a blank page on the production build (a functional setState updater reads event.currentTarget after dispatch), the PWA offline fallback is broken (precached /offline.html is a 307 redirect so offline navigation ends in net::ERR_FAILED), a 57 KB PNG favicon plus ~397 KB of SW precache compete with the critical JS on mobile, the template catalog is 702 KB decoded (95 KB gz) for a chooser that needs ~48 KB, and ~181 KB of dead Manrope/Newsreader woff2 ship in the build. Ranked by user-visible gain per effort: (1) fix the updater crash, (2) fix the offline precache path, (3) tiny favicon + optimized icons + long cache headers + trim precache, (4) slim catalog endpoint, (5) per-screen code splitting and critical CSS during the redesign (~0.5 s on Fast 3G), (6) server-fetch or preload the workspace JSON to remove the post-hydration waterfall (~0.2 s), (7) OCR prefetch/size disclosure, (8) font budget/strategy for the new display face, (9) gateway/landing hygiene. I could not find the referenced "SSR/first-paint waterfall (architectural)" deferred note in docs/ or git history (the only explicit deferral is the Stripe/ads Phase 2), but the waterfall itself is real and measured.

## security

The core authorization model is solid: the Railway gateway strips client-supplied oai-*/identity headers and injects a trusted identity, every workspace and evidence query in route.ts/db/runtime.ts is parameterized and scoped to user_id = identity.userId (the handful of ${} SQL interpolations are compile-time constants or ?-placeholder builders), client-supplied userId is rejected, sessions rotate on login and are killed on password reset, passwords use scrypt+salt with a dummy-hash existence-oracle guard, and the internal cron route is double-gated. Evidence upload validation (magic bytes, size, filename sanitization, key built from validated ids) and the CSRF posture on the JSON command endpoint are genuinely good. The most serious issue is the widget feed: it bypasses gateway auth, is gated only by one shared static token that shipped in the (now-retired) iOS binaries, always serves the OLDEST account's credential names/deadlines/progress regardless of who calls, and I confirmed the token is configured in production (401, not 503) — a live cross-tenant PII exposure. Secondary issues are the total absence of security headers in prod (no HSTS/CSP/X-Frame-Options/Referrer-Policy/Permissions-Policy), a verify-by-GET flow that both burns the single-use token and mints a session (mail-scanner hostile), account enumeration on signup/login, a 5-minute Basic-auth cache that honors old credentials after a reset, and a rate-limiter whose correctness rests on an unverified assumption about Railway's x-forwarded-for ordering. Retiring the iOS shell cleanly removes the two biggest attack-surface items (the widget bearer exemption and Basic auth entirely).

## architecture

The client is one 10,953-line file whose shell component `ITrackApp()` (lines 1656–6511, 4,856 lines) holds 43 useState / 10 useRef / 19 useEffect / 10 useMemo / 11 useCallback plus 45 inner functions, and renders 9 modals inline that close over 4–38 shell identifiers each; the five screens and the allocators are already prop-driven leaf components (TodayView 1,017 lines/23 props, CredentialDetailScreen 428/13, RecordsView 347/11, AccountView 458/15), so they can move verbatim, but the modals, the single global `error` string (54 setError sites), the shared FORM pending key and the hidden `selectedCredentialId` subject have to be redesigned into explicit props/hooks. The code itself is healthy — tsc and eslint are clean, contrast-audit passes 98 claims, there are no TODOs, and the event.currentTarget-after-await bug count is zero (all 8 async handlers capture synchronously) — but it is coupled to the retired platforms: a broken `/signout-with-chatgpt` sign-out link (404), Capacitor haptics, 3,747 lines of APNs/widget code, a gateway User-Agent gate that exists only for the WKWebView, and a literal "L" (License Lantern) glyph on every empty state. `globals.css` (6,618 lines, 145 tokens, 653+180 rule blocks) is not dead-heavy (0 unused class selectors, 2 unused tokens) but is cross-cut: every screen's responsive rules live in four trailing media blocks and 44 selectors are declared twice, and `tools/contrast-audit.mjs` assumes a single file.
